# 管理画面の共通仕様書

VehicleVision.PleasanterTools の各アプリの**管理画面のうち、共通にできる部分**の仕様。
Questionnaire（Q）の実装を比較の基点とし、2026-10-22 のユーザー決定を共通の規範とする。
AtomFeed・CalendarFeed・IdentityProvider（IdP）を含め、決定に追いついていない実装は「現状との差」として記録する。
コードを共有できない所（各アプリの画面・認証の入口の細部）は、**この仕様書と契約テストでそろえる**（Issue #73）。

**決定後の規範と、実装から確かめた現状を区別する。**
確かめていない動作は「未確認」、決定を具体化するための追加判断はその旨を明記する。

## 1.1 なぜ要るか

各アプリの管理画面は、コピーから別々に育った。**同じ目的の流れが、アプリごとに違う形で実装されている。**

- Q では `/api/admin/enroll/begin` が、TOTP を登録済みの管理者でも受け付けていた。パスワードだけで自分の鍵へ差し替え、
  2 要素目を迂回できた（Q#695。Q の PR #701 で修正）。AtomFeed・CalendarFeed には、その流れ自体が無い
  （ログイン途中の登録は `/me/totp/*` を兼用し、「必須かつ未登録」に限っている）
- 逆に、AtomFeed・CalendarFeed は**ログイン後の登録し直しにパスワードの再確認を求めない**が、Q は求める
- 経路の接頭辞（`/api/admin` と `/admin/api`）、エラー本文の形、監査ログの `Action` の名前も違う

この仕様書は、後続の「Core.Web（共有コード）」と「契約テスト」の元にする。
