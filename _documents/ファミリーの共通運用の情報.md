# ファミリーの共通運用の情報

[README のファミリー紹介](../README.md)を補う、開発者向けの情報。
2026-10-22 に共通のテンプレートと Core のワークフローを確認した。
社内用 Template へのリンクは、公開する資料には載せない。

## テンプレートからの作成

新しいツールは社内 Template から作り、`New-FromTemplate.ps1` でプロジェクト名などを置き換える。
README・NOTICE・設計資料・ライセンスを実態に合わせ、公開時には CLA と GitHub の共通設定を整える。
共通部品はコピーせず、NuGet の Core を必要なものだけ参照する。
採用範囲とアプリ固有の値の渡し方は[コア化の方針](コア化の方針.md)を参照。

根拠: Template の `_documents/開発ガイド.md`「新しいツールを作る」、
`scripts/New-FromTemplate.ps1`（`develop`、`60ad8ae`、2026-10-22 参照）。

## patch 更新

npm・NuGet の同じ major.minor 内の patch 更新を検出し、ロックファイル・NOTICE まで合わせて PR にする。
必須チェックが通れば自動マージする。土台は `master`、まだ無ければ `develop`。
`master` へ入れた更新は、同期 PR で `develop` に戻す。失敗や衝突は人が確認する。

根拠（2026-10-22 参照）:
[更新ワークフロー](../.github/workflows/patch-updates.yml)、
[同期ワークフロー](../.github/workflows/patch-updates-sync.yml)、
[更新スクリプト](../scripts/apply-patch-updates.mjs)。

## 設定の監査

社内 Template の `Test-RepoAudit.ps1` で、GitHub 設定・ルールセット・必須チェック・ラベル・CLA、
共通ファイル、Core の参照版と nuget.org の掲載版の差を読み取り専用で調べる。
Actions の資格情報は名前の有無だけを確認する。値は記録せず、設定の自動修復もしない。
差分と、権限不足などで確認できない項目は区別し、結果を人が確認する。

根拠: Template の `_documents/開発運用.md`「共通設定の読み取り専用監査」、
`scripts/Test-RepoAudit.ps1`（`develop`、`60ad8ae`、2026-10-22 参照）。
この監査スクリプトは Core に同梱していない。
