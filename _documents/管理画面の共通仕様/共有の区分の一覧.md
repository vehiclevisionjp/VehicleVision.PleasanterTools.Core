# 管理画面の共有の区分の一覧

[管理画面の共通仕様書](../管理画面の共通仕様書.md)の 12 章。何を共有し、何を共有しないかを部品ごとに決める。

区分:

- **C#**: 共有できる。C# のコードを Core.Web（新しいパッケージ。仮の名前）へ移す
- **npm**: 共有できる。Svelte の部品として、将来 npm で配る
- **仕様**: 仕様だけ共有する。コードは各アプリが持ち、この仕様書と契約テストでそろえる
- **固有**: アプリ固有。共有しない

現状: 「同じ」= アプリ名を除いて同一、「似ている」= 目的と形は同じで細部が違う、「別物」= 設計が違う、「無い」。
Q を基準にした比較。AF と CF は A.4 のとおりほぼ同一なので 1 列にまとめる。

## 12.3 結論

- **すぐ C# で共有できる**のは、AF と CF の**同一のファイル**（A.4）と、どのアプリでも形の同じ基盤
  （ハッシュ・TOTP・パスワードの条件・招待トークン・設定ファイルの読み込み・メッセージの仕組み）
- **認証の入口は、まず仕様と契約テストで共有する**。Q と AF・CF で経路・応答・登録の流れが違い、
  そのまま 1 つのコードにすると、どちらかのアプリの挙動を黙って変えることになる（第 3・4 段階）
- **IdP は管理者の設計が別物**。共有するのは監査ログのストア（済み）と、パスワード以外の基盤の一部と、
  画面の部品の一部にとどめる
