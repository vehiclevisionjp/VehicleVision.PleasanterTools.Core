# 管理画面の契約テストの方針

[管理画面の共通仕様書](../管理画面の共通仕様書.md)の 10 章。
**C1〜C5 の共有テストは preview.11 で公開済み。Q の正式参照・通常 CI への接続も完了した**（Issue #80）。
U1〜U14 の決定で増える候補は 10.4.1 に記す。
**Issue #90 で C7・C10・C12・C13・C14・C19・C20・C21 の HTTP 契約を追加した（未公開）**。
実装した範囲・内部条件との境界・アプリ別の見込みは 10.6。ほかの候補を実装済みとは扱わない。
仕様書の不変条件を、**アプリに依存しない形**で、HTTP の層から確かめるための足場を決める。

## 10.1 ねらい

- 同じ不変条件を、アプリごとに書き写した試験で守ると、**試験もコピーと同じくばらつく**。
  Q#695 は「`/enroll/begin` が登録済みの人を受け付ける」欠陥で、AtomFeed・CalendarFeed には流れ自体が無かった
  （[各アプリの差異の一覧](各アプリの差異の一覧.md)）。**流れがあるアプリ・無いアプリを同じ物差しで測れる**ようにする
- 試験は**実装ではなく契約（経路・状態・本文の形・cookie）**を見る。Core.Web へ寄せる途中でも、寄せた後でも同じ試験が通ること

## 10.2 置き場所

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. Core のテスト用ライブラリ（採用） | `VehicleVision.PleasanterTools.Core.Web.Testing` を NuGet で配り、各アプリの試験プロジェクトがホストを実装して参照する | 不変条件を 1 か所で直せる。Core の版を上げれば全アプリに効く | アプリごとの差（経路の有無・初期データの作り方）を吸収する口が要る |
| B. 各アプリに書き写す | 各アプリの `Integration.Tests` に同じ試験を置く | すぐ始められる | **コピーが育つ**（コア化の方針の背景そのもの） |
| C. 外から叩く黒箱の試験（別リポジトリ） | 起動したアプリへ HTTP で当てる | 言語・構成を問わない（IdP も同じ物差し） | 初期データ（管理者・TOTP）を外から作れない。CI が重い |

**A を採用し、`VehicleVision.PleasanterTools.Core.Web.Testing` として配布する**（preview.11 公開済み）。
アプリの差は「能力の宣言」で吸収する。C は IdP のように設計が違うアプリで、
入口の存在だけを確かめる用途に限る。U9 の置き場所はこれで決定した。

### 10.2.1 アプリが実装するもの

```csharp
public sealed class AdminContractTests : AdminAuthenticationContractTests
{
    protected override async Task<IAdminContractHost> CreateHostAsync() =>
        await AppAdminContractHost.StartAsync();
}
```

`AppAdminContractHost` はアプリ側の実装例の名前。ホストは **1 試験ごとに作成・破棄**される。
基底クラスが持つ `Fact` / `Theory` が、継承先の xUnit 試験として発見される。
公開済み C1〜C5 は 16 件。今回の追加は 49 件（能力未宣言の場合の扱いは 10.6.2）。

| 公開 API | アプリが渡すもの |
|---|---|
| `IAdminContractHost` | `IAsyncDisposable`。設定・能力・HTTP クライアントと、下記の準備用ヘルパ |
| `CreateClient()` | 空の独立した cookie 容器を持つ `HttpClient`。転送を追わず、同じホストへ接続する |
| `SeedAdminAsync(withTotp, disabled)` | 管理操作の権限を持つ、一意な ID の利用者を作る。必要なら TOTP を登録・利用者を無効化する |
| `SeededAdmin` | ログイン ID とパスワード。共有テストへ鍵や DB の型は渡さない |
| `LoginAsync(client, admin)` | パスワードだけを **HTTP で**照合し、加工していない応答を返す |
| `NextTotpCode(admin)` | サーバが受け付ける未使用の時間枠の数字 |
| `AdminContractCapabilities` | 存在する `AdminContractOperation` の集合 |
| `AdminContractSettings` | 全操作の経路と方法、要求本文への変換、次の段階の項目名と値、ログイン失敗の JSON の形 |
| `AdminContractEndpoint` / `AdminContractInput` | 方法・経路と、ID・パスワード・コードなどをアプリの JSON 本文へ変換する関数 |
| `AdminContractCookies` | Session・Pending・Reenroll の異なる cookie 名 |

- `SeedAdminAsync` は Core.Data のストアでも、アプリ独自のストアでもよい。
  共有ライブラリは DB・ASP.NET Core・アプリ本体を参照しない。依存は既存と同じ xUnit 2.9.3 だけ
- 経路は接頭辞も含めてアプリが指定する。共有側は `/api/admin` と `/admin/api` を知らない。
  本文も `{password}` などを決め打ちせず変換する。状態コード・失敗回数は設定で緩められない。
  これは移行中の差を検出する足場であり、U3 決定後の形の一致は C15 で別に固定する
- 能力が「無い」場合も探査先を指定する。試験を飛ばさず **404 を要求**する。設定漏れは初期化時に失敗する
- C1〜C4 の存在する入口を試すには、パスワードと TOTP のログインが要る。
  登録し直しの完了には開始の入口も必要。矛盾した能力宣言は拒む。
  **別方式で認証する IdP への適用は未実装**。全入口が無い場合の 404 確認とは区別する
- C3 は独立したクライアントへ Reenroll の cookie だけを移し、Session が紛れ込まないようにする。
  Pending の名前へ付け替えた場合も拒否を要求する
- C5 は同じ `Accept-Language: en` で、状態と JSON の形に加えて **本文の値も一致**させる。
  翻訳の具体的な文言は共有側に置かない
- C2 は 5 回の失敗すべてに 401、直後の正しいパスワードにも締め出し中の 423 を要求する。
  上限到達の要求を 423 にする選択肢は追加しない（U15）。
  AF・CF は登録し直しの再確認が無く、IdP はこの認証方式を使わないため、設定で差を隠さず A.2 に残す
- Q の `TotpService` は時計を注入できない。Q のホストは未使用の枠で直接登録し、実時刻で数字を作る。
  時計の固定・時間切れの試験を済ませたとは扱わない

根拠（2026-10-22）:
`src/VehicleVision.PleasanterTools.Core.Web.Testing/IAdminContractHost.cs:4`、
`AdminContractSettings.cs:7,21,28,39,57,60`、
`AdminAuthenticationContractTests.cs:8,36,54,70,83,116,143,162,178`（同ディレクトリ）。
自己検証は `tests/VehicleVision.PleasanterTools.Core.Web.Tests/AdminContractTestsTests.cs:10`。

## 10.3 HTTP の層で確かめること

この節は最終的な対象。C1〜C5 に加え、今回追加した HTTP 検査の範囲は 10.6.1。
**cookie 属性・キャッシュ・監査ログの検証はまだ無い。**

- 状態コード（401・403・404・409・423）と、エラー本文の形（`{message}` か `{code}`）。**文言は見ない**（言語で変わる）
- cookie の名前・属性（`HttpOnly`・`SameSite`）・中身が ID だけであること（cookie の長さや形）
- 応答の `Cache-Control`
- 監査ログに行が増えたか（`IAuditLogStore.ListAsync` で `Action`・`Succeeded`・`StatusCode` を見る。本文の秘密が入っていないこと）

### 10.4.1 決定で追加する不変条件の候補（全体像）

試験番号は着手順ではない。アプリ別の対応は 11.5〜11.8。

**HTTP だけで分からない内部条件を HTTP の成功で代用しない**。
Issue #90 では C7 の物理削除、C19 の保存形式、C22 のハッシュ形式を HTTP 契約から除外した。
ストア・暗号の単体試験と移行試験は各アプリに必要（10.6.3）。
C17・C18 は隔離した起動プロセスと設定・鍵ファイル・DB の前後を検査する別の足場が必要で、今回の範囲外。

`IAdminContractHost` に権限分離・設定切り替え・外部ログインなどの省略可能な準備口を追加した（10.6.2）。
C10 は試験用の権限表などで `users.read` と `users.resetTwoFactor` を分離する。
C13・C14・C20 の署名付き SAML 応答と Pleasanter の検証先はアプリのホストで隔離する。
C20 は有効・期限切れなどの状態を検査するが、未決の時間幅や要求形式は固定しない。
C23 の署名付き SLO・時計の共通注入・監査の観測は未実装。現行パスワード経路の C2 は緩めない。

IdP には存在しない管理者・招待・再登録 API を追加しない。
適用外の根拠は 11.7 に残し、決定済みの差を能力の未宣言で解決済みと扱ったり、
IdP の `/login` の HTML 応答を JSON とみなして成功扱いしたりしない。

### 10.5.1 Q での結果と仕様の決定

変更前の検証（2026-10-22）は、Q `004766d` を基点に、実際の `Program` を `WebApplicationFactory` で起動した。
試験ごとに専用の SQLite DB へ本体のマイグレーションを当てる。送信ワーカーは外し、
認証・認可・管理 API・ストアは本体を使う。本体コードは変更していない。
一時的な `ProjectReference` と、ローカルで pack した NuGet の参照の両方で、同じ結果になった。

| 契約 | 件数 | 結果 |
|---|---|---|
| C1 | 2 | 成功。登録の開始・完了は 403、その後も元の TOTP でログイン可能 |
| C2 | 4 | 3 成功・1 失敗。未指定・誤ったパスワードは 401、正解は 200 と Reenroll cookie |
| C3 | 6 | 成功。cookie 単独・名前の付け替えで認証段階を取り違えられない |
| C4 | 3 | 成功。Pending の管理者一覧・パスワード変更・監査一覧は 401 |
| C5 | 1 | 成功。存在しない人・誤り・無効の人は同じ 401 と本文 |

変更前の C2 の不一致は、5 回の失敗がすべて 401 となり、次の正しいパスワードで 423 になることだった。
DB 上の締め出しは作動している。2026-10-22 のユーザー判断で、**仕様を Q の実装に合わせる**と決定した（U15）。
上限に達した失敗の要求自体は通常と同じ 401（理由を区別しない）、**その次の要求から 423**。
